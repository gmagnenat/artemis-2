## Problem Statement

Build a stunning, design-forward Artemis II mission dashboard that combines real-time NASA data with premium visual design. The Artemis II mission launched April 1, 2026 and is a ~10-day lunar flyby with 4 astronauts. Existing community trackers are functional but visually generic. This project fills the gap between "engineering tool" and "designed experience" by applying modern sports-brand aesthetics (Lando Norris website inspiration) to live space mission data.

## What Makes This Cool

The emotional hook: making 4 humans flying around the Moon *feel* real and cinematic, not just a dot on a map. Astronaut trading cards with holographic shimmer. A Three.js Earth-Moon scene you can stare at. Mission data presented like a premium sports broadcast, not a telemetry console. Nobody has combined this level of design craft with space mission data.

## Constraints

- **Time-sensitive:** Mission is live NOW (launched April 1, ~10 days). Every day of delay is a day less of "live" experience.
- **No backend:** Static site with client-side API calls. Free deployment (Vercel/Netlify).
- **No paid APIs:** All data from NASA open sources (AROW, api.nasa.gov, YouTube/RSS).
- **Browser performance:** Three.js scene targets 30fps at 1080p on iPhone 12 equivalent. Use `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, low-poly Earth mesh. On mobile (< 768px), replace 3D with a static SVG trajectory illustration.
- **Post-mission:** After splashdown (`Date.now() > splashdownTimestamp`), archive mode activates: countdown becomes "Mission Complete: X days, Y hours," trajectory shows the full completed path, all data is frozen at final values with timestamps.
- **Degraded states:** If an API call fails or data is stale, show last-known values with a "Last updated: [timestamp]" badge. Never show a blank section, always fall back to hardcoded snapshot data.
- **CORS:** AROW/OEM endpoints may not serve CORS headers for browser fetch. If CORS is blocked, use a Vercel Edge Function as a thin proxy (still free tier, still no backend in spirit).

## Premises

1. Data sources: NASA AROW/OEM trajectory data, api.nasa.gov (APOD, astronaut info), public YouTube/RSS for news. No proprietary or paid APIs needed.
2. Three.js is the right choice for 3D trajectory visualization.
3. The differentiator is design quality, not data accuracy. Existing trackers already show the data.
4. Static site with client-side API calls. No backend needed.
5. After the mission ends, this becomes an archive/portfolio piece.

## Approaches Considered

### Approach A: Cards-First Sprint (CHOSEN)
Start with astronaut trading cards + hero section. Establish the design system. Add 3D scene second, feeds last. Ship incrementally.
- Effort: M (weekend for cards + hero, another weekend for 3D + feeds)
- Risk: Low
- Pros: Fastest to showable, design system emerges organically, each section self-contained
- Cons: 3D comes later, might feel incomplete initially

### Approach B: 3D Hero First
Full-screen Earth-Moon Three.js scene as hero, data overlaid, cards below.

## Recommended Approach

**Approach A: Cards-First Sprint.** The mission is live now. Having something beautiful to show colleagues this week beats having a perfect architecture next month. The timeline scrubber (Approach C) can be added as v2 after the foundation is solid.

### Build Order
1. **Hero section + design system** — Dark theme, typography (suggest: Space Grotesk or similar geometric sans), color palette, grain/noise textures, glassmorphism panels
2. **Astronaut trading cards** — 4 cards with parallax tilt (vanilla JS `mousemove` → `transform: perspective(1000px) rotateX() rotateY()`), holographic shimmer (CSS `conic-gradient` shifted on mouse position, similar to the Pokemon card CSS technique), flip on click to show stats. Hard-coded astronaut data from NASA bios (Reid Wiseman, Victor Glover, Christina Koch, Jeremy Hansen)
3. **Mission status bar** — Mission elapsed time, distance from Earth, distance from Moon, current phase. Pull from AROW data.
4. **Simple 3D scene** — Earth + Moon + trajectory path + Orion position dot. Not fully polished, but the backbone. Initially use a hardcoded OEM snapshot captured at build time; upgrade to live polling once AROW API access is confirmed.
5. **News/comms feed** — NASA RSS/YouTube embed. Lower priority but completes the experience.
6. **Polish** — Scroll animations (GSAP: cards fade-in on scroll, mission status bar pins at top, 3D scene enters on scroll past hero), performance optimization, responsive design, static OG image (pre-rendered PNG, no dynamic generation).

### Tech Stack
- **Framework:** Astro (static export, lighter than Next.js, consistent with "no backend" constraint; Three.js integrated via vanilla JS or a React island)
- **3D:** Three.js (via @react-three/fiber if React, or vanilla)
- **Animation:** GSAP + ScrollTrigger for scroll-driven reveals
- **Styling:** Tailwind CSS for rapid iteration on dark theme
- **Data:** NASA AROW API (trajectory), api.nasa.gov (APOD, astronaut bios), NASA RSS feeds
- **Deployment:** Vercel (free tier)

### Data Sources
- **Trajectory:** NASA AROW (Artemis Real-time Orbit Website) — OEM ephemeris data
- **Astronaut info:** api.nasa.gov + Wikipedia/NASA bios (can be hardcoded, only 4 people)
- **News:** NASA RSS feeds, YouTube embed (no API key needed, consistent with no-backend constraint)
- **Mission imagery:** NASA Image Gallery (public domain)
- **Audio:** Deferred to v2 (browser autoplay restrictions make this complex; revisit with timeline scrubber)
